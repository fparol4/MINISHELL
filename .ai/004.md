# Basic Test Plan

## Goal

- Keep tests simple while modules are being ported.
- Use `tests/` for focused checks around each integration step.
- Avoid Makefile/test-target cleanup until the final build-system pass.
- Avoid Norminette/style tooling for now.

## Current Test Layout

- `tests/envm.c`: env manager tests.
- `tests/bultin.c`: builtin tests, name cleanup deferred.
- `tests/runner.c`: includes runner test groups.
- `tests/runner/*.c`: command, pipe, redirection, expansion, status, signal tests.
- `tests/mocks/parser_results.md`: executor-side parser result examples.

## Core Test Plan

- Add `tests/core.c` when we are ready to compile tests manually.
- Test `core_init()` with a small env array like `A=1`, `PWD=/tmp`, `SHLVL=1`.
- Assert `shell.env` is initialized.
- Assert `shell.running == TRUE` after init.
- Assert `$?` is initialized as `0`.
- Call `core_destroy()` and assert `shell.env == NULL` and `shell.running == FALSE`.
- Test `core_init()` with `envp == NULL` to confirm minimal env creation works.
- Do not test `core_loop()` through readline directly yet; keep it for manual smoke testing until input can be injected.

## Manual Core Smoke Test

- After Makefile includes `source/core/*.c`, build the binary.
- Run `./minishell`.
- Confirm prompt appears.
- Press `Enter` on empty input and confirm it keeps running.
- Type any non-empty text and confirm it does not crash.
- Press `Ctrl-D` and confirm clean exit.
- Press `Ctrl-C` at prompt and confirm it returns to prompt without exiting.

## Lexer Test Plan

- Port or create `tests/lexer.c` after lexer source is in `source/`.
- Test words, quoted words, pipes, redirections, append, heredoc.
- Assert token order, token type, value, and `expand` flag.
- Test unclosed quotes returns the expected syntax error path.
- Test lexer cleanup on empty input and allocation failure paths if feasible.

## Parser Test Plan

- Port or create `tests/parser.c` after parser source is in `source/`.
- Test simple command: `echo hi`.
- Test pipe: `echo hi | wc -c`.
- Test redirections: `<`, `>`, `>>`, `<<`.
- Test redirection order preservation.
- Test syntax errors: starting pipe, ending pipe, missing redirection target, empty command.
- Test parser cleanup for ASTs with nested pipes and multiple redirections.

## Integration Test Plan

- After parser connects to executor, add a small end-to-end test file or manual scripts.
- Test simple builtins: `echo`, `pwd`, `env`.
- Test external command execution: `/bin/echo hi` or `echo hi` through PATH.
- Test `$?` after success and failure.
- Test pipes with external commands.
- Test redirections and heredoc behavior.
- Test expansion inside argv and heredoc body.

## Notes

- For now, prefer manually compiling specific test files with the exact source files needed.
- Keep test code close to current module boundaries.
- Do not rewrite the existing runner tests until parser output conversion is decided.
