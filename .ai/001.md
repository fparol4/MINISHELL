# Merge Overview: `main` into `dev/merge`

- Current branch inspected: `main`; `dev/merge` points to the same commit as `dev/fabricio` (`57ec57b`).
- `main` is the lexer/parser branch and introduces the new project layout: `includes/`, `src/`, `infra/`, `libft/`, lowercase `makefile`, parser/lexer tests, and syntax-error handling.
- `dev/fabricio` is the executor branch and uses the older layout: `headers/`, `source/`, `tests/`, uppercase `Makefile`, env/builtin/runner modules, and parser mock docs.
- The diff is effectively a project-structure replacement: `main` deletes the executor/env/builtin files from `dev/fabricio`, while `dev/fabricio` lacks the new lexer/parser files from `main`.

## Parser Result Structs

- `dev/fabricio` executor expects `t_exnode` from `headers/minishell.h`.
- `t_exnode` fields are public/direct: `type`, `args`, `redir`, `left`, `right`.
- `dev/fabricio` node types are `CMD` and `PIPE`.
- `dev/fabricio` redirection types are `IN_F`, `IN_H`, `OUT_T`, `OUT_A`.
- `dev/fabricio` redirections are a linked list: `t_redir { type, target, expand, next }`.
- `main` parser returns `t_ast` from `includes/public/parser.h`, with `root`, `size`, `error`, and `error_type`.
- `main` parser root is `t_command`, defined internally in `includes/private/parser_internal.h`.
- `main` node types are `NODE_CMD` and `NODE_PIPE`.
- `main` command payload is behind a union: `cmd->t_define.simple` or `cmd->t_define.pipe`.
- `main` redirection types are `REDIR_IN`, `REDIR_OUT`, `REDIR_APPEND`, `REDIR_HEREDOC`.
- `main` redirections are a dynamic array: `t_redir *redirs` plus `redir_count`.
- `main` redirection target field is named `file`; `dev/fabricio` executor expects `target`.
- `main` stores an `expand` flag per token/redirection and also has `t_simple.expand`; executor currently expands all argv through `rn_expand()`.

## Integration Notes

- The executor cannot consume `main` parser output directly because type names, enum values, field names, and redirection storage differ.
- The smallest merge path is likely to keep `main` lexer/parser as source of truth and adapt the executor to `t_ast`/`t_command`, or add a thin AST-to-executor conversion layer.
- Redirection handling needs explicit mapping from `REDIR_*` to executor semantics and conversion from redirection array order to runner order.
- Pipe execution maps cleanly conceptually: `NODE_PIPE.left/right` corresponds to executor `PIPE.left/right`.
- Simple command execution maps conceptually: `t_simple.args` corresponds to executor `args`.
- Heredoc expansion behavior should be checked carefully: parser provides `expand`; executor uses it for heredoc body expansion.
- Build-system merge will be non-trivial because `main` and `dev/fabricio` use different file trees and makefiles.
