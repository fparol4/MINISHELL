# Pre-Work Check: Typos and Missing Functions

## Scope

- Current branch: `dev/merge`.
- Source branch being inspected for porting: `main`.
- This is only the check phase; no source files were renamed or ported yet.
- Makefile/test-target updates are intentionally deferred until the end.
- Norminette and other norm/style tool checks are intentionally out of scope for now.

## Existing Build State

- `make` currently reaches the link step but fails because `source/main.c` has no `main()` implementation.
- Link error: `undefined reference to main`.
- This is expected to be solved during the `source/core` port.

## Typo / Naming Corrections

- `source/modules/bultin/` should become `source/modules/builtin/`.
- `tests/bultin.c` should become `tests/builtin.c`.
- Makefile variable/target updates for this rename should be done at the final build-system pass, not now.
- `lexer_controll` from `main` should become `lexer_control` or `lexer_controller` before/while porting lexer.
- `L_DOLAR` from `main/includes/private/lexer_internal.h` should become `L_DOLLAR`.
- `t_define` in parser internals is awkward naming for a union member; consider renaming to `data` or `u` when parser is ported.
- `envm` appears to mean environment manager; leave it unless the team wants a broader module rename.

## Type Corrections Needed Before Porting

- `main` uses `t_bool` from its own `libft.h`; `dev/merge` libft/shared headers do not define it.
- Add one shared boolean type in `dev/merge`, preferably in a common public header used by lexer/parser/executor.
- `main` lexer uses `t_node` and `t_manager` for token lists.
- `dev/merge` libft already has a different `t_node` for stack internals, so importing `main` linked-list types directly will conflict.
- Avoid copying `main/libft/linked_list/linked_list.h` as-is into `dev/merge`.
- Prefer parser/lexer-specific names such as `t_token_node` and `t_token_manager`, or adapt lexer to existing `t_list`.

## Missing Functions Required By Lexer/Parser Port

- `ft_create_node`: used by `main/src/lexer/lexer_manager.c`; missing in `dev/merge` libft.
- `ft_dlist_add_back`: used by `main/src/lexer/lexer_manager.c`; missing in `dev/merge` libft.
- These two should probably not be added to libft with the original `t_node` signature because of the `t_node` conflict.
- Better option: move them into lexer internals with renamed token-list types, or rewrite lexer manager to use existing `t_list` helpers.
- `dynarray_append`: used by parser state; not a libft function in `main`, it belongs to `infra` and must be ported with parser/infra.
- `scanner_*` helpers and `init_char_table`: not libft functions; they belong to `infra` and must be ported before lexer.

## Main Libft Functions Missing Or Differently Named In Dev Libft

- `ft_jump_space`: public in `main/libft.h`; missing in `dev/merge` libft. Not required by current lexer/parser port scan.
- `ft_msg_error`: public in `main/libft.h`; missing in `dev/merge` libft. Not required by current lexer/parser port scan.
- `get_next_line`: implemented in `dev/merge` under `libraries/libft/lib/ft_gnline/get_next_line.c`, but `libraries/libft/libft.h` declares `ft_get_next_line` instead.
- `ft_lst_new`, `ft_lst_add_back`, `ft_lst_add_front`, `ft_lst_size`, `ft_lst_last`, `ft_lst_del_one`, `ft_lst_clear`, `ft_lst_iter`: `main` uses underscore names, while `dev/merge` libft already has equivalent canonical names without the extra underscore.
- `ft_dlist_iter`: present in `main` linked-list helpers; missing in `dev/merge`. Only needed if we port tests/debug iteration directly.
- `ft_pointer_printf`, `ft_printcstr_printf`, `ft_puthex_printf`, `ft_putnbr_printf`, `ft_putunbr_printf`: present in `main` printf implementation but not needed if we keep `dev/merge` libft printf.

## Suggested Fix Order

- First add/centralize `t_bool`.
- Rename `bultin` to `builtin` in source/test paths when we touch that module; defer Makefile updates to the final pass.
- When porting lexer, rename `lexer_controll` and `L_DOLAR` immediately.
- Do not add `main` linked-list types to libft unchanged; resolve the `t_node` conflict first.
- Fix `libft.h` `get_next_line` prototype mismatch if core/runner should include it through `libft.h`; otherwise keep using the specific GNL header.
- Add only genuinely needed libft functions after the lexer/parser compile errors confirm they are required.
